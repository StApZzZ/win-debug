# win-debug

[English](README.md) | Русский

**win-debug** - набор диагностических инструментов «только для чтения» для компьютера с Windows 10/11, который «стал тормозить». Он отвечает на три вопроса, ничего не меняя на машине: *что это за компьютер и что с ним не так* (Инвентаризация), *что занимает диск* (Использование диска) и *что работает в фоне, когда никто не смотрит* (Монитор + Анализ - фоновая запись процессов и система оценки, настроенная на поиск криптомайнеров и других пожирателей ресурсов). Всё записывается в папку отчёта в виде файлов Markdown, JSON и CSV, которые можно прочитать на месте или унести на флешке. Ничего не отправляется в интернет, ничего не устанавливается, ничего не удаляется.

## Требования

- Windows 10 или Windows 11, 64-разрядная.
- Windows PowerShell 5.1 - предустановлен в любой поддерживаемой Windows. PowerShell 7 **не** нужен и не используется.
- Права администратора не обязательны, но желательны: без них отчёты честно перечисляют, что было пропущено (пометка `(requires administrator)`).
- Не нужен интернет, ничего не устанавливается, никаких сторонних программ. Два небольших вспомогательных модуля на C# компилируются в памяти при запуске компилятором .NET Framework, входящим в состав Windows (нужна доступная для записи папка `%TEMP%`; если компиляция не удалась, инструмент переходит на более медленный код на чистом PowerShell).

## Быстрый старт

1. Скачайте репозиторий в виде ZIP (на GitHub: *Code -> Download ZIP*).
2. Правой кнопкой по ZIP -> *Свойства* -> поставьте галочку **Разблокировать** -> ОК (или в PowerShell выполните `Unblock-File .\win-debug.zip`). Это снимает отметку «загружено из интернета» со всех файлов внутри ещё до распаковки.
3. Распакуйте в **локальную** папку, например `C:\Tools\win-debug`. Не запускайте с сетевого диска, из пути вида `\\server\...` или из WSL - инструмент отказывается работать оттуда с кодом выхода 2.
4. Дважды щёлкните **`WinDebug.cmd`**.
5. Меню открывается с текущими правами - двойной щелчок сам по себе никогда не вызывает запрос UAC. Выберите в меню пункт **A**, чтобы перезапустить инструмент с правами администратора (рекомендуется для полной картины). При прямом запуске режима (`WinDebug.cmd inventory|disk|monitor|all`) инструмент сначала спрашивает `Run with administrator rights for a complete picture? [Y/n]` - Enter означает «да» и вызывает запрос UAC; если отказаться, он продолжит с текущими правами.
6. Выберите пункт меню:

```
 win-debug 1.0.0  —  read-only Windows diagnostics          Administrator: NO (some data will be missing)
 Reports folder: C:\Tools\win-debug\reports

  1  Inventory     hardware, drivers, software, autostart, security, event logs  (~1-2 min)
  2  Disk usage    what occupies the disk and what could be freed                 (~2-5 min)
  3  Monitor       record processes / CPU / GPU / network in the background      (runs until stopped)
  4  Analyze       build report.md from a recorded monitor session
  5  All           Inventory + Disk usage
  6  Install monitor as logon task ("WinDebug Monitor")
  7  Remove the logon task
  8  Stop a running monitor
  A  Restart with administrator rights
  Q  Quit
```

По окончании режим печатает `Done. Report: <папка>`. Каждый запуск получает свою папку внутри `reports\` с именем `<ИМЯ_КОМПЬЮТЕРА>_<ггггММдд-ЧЧммсс>_<inventory|disk|monitor>`; начинайте с `summary.md` (Inventory, Disk) или `report.md` (Analyze). Интерфейс и отчёты на английском языке.

### SmartScreen и политика выполнения

- При первом двойном щелчке SmartScreen может показать *Система Windows защитила ваш компьютер*. Нажмите **Подробнее -> Выполнить в любом случае**. Лаунчер - обычный файл `.cmd`, который запускает `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe -NoProfile -ExecutionPolicy Bypass -File WinDebug.ps1` (полный путь к хосту Windows PowerShell 5.1, а не «голый» `powershell.exe` из текущей папки или `PATH`); ничего не устанавливается.
- Ключ `-ExecutionPolicy Bypass` обходит политику *Restricted*, действующую по умолчанию на домашнем ПК, не меняя никаких настроек. Политику, заданную групповой политикой (корпоративные машины), он обойти не может - см. [Устранение неполадок](#устранение-неполадок).
- Если вы пропустили шаг 2 и видите `... is not digitally signed` или `AuthorizationManager check failed`, разблокируйте распакованные файлы: откройте PowerShell в папке и выполните `Get-ChildItem -Recurse | Unblock-File`.

В каждой папке отчёта есть также `run.log`. Подробности: [docs/inventory-rules.md](docs/inventory-rules.md) (каждое правило Inventory и Disk с порогом - 150 идентификаторов правил Inventory и 19 правил Disk), [docs/monitor-format.md](docs/monitor-format.md) (каждая колонка монитора), [docs/analyze-scoring.md](docs/analyze-scoring.md) (каждый индикатор Analyze и формула оценки).

Числа во всех файлах используют точку как десятичный разделитель независимо от языка Windows, время записывается в ISO 8601 со смещением (`2026-09-27T23:08:17.742+03:00`), CSV - UTF-8 с BOM (открываются в Excel напрямую), JSON/Markdown/журналы - UTF-8 без BOM. Во всех CSV-файлах (Inventory, Disk, Analyze и файлы монитора) текстовая ячейка, начинающаяся с `=`, `+`, `@`, табуляции или с `-` (если только вся ячейка не является числом: `-5`, `-1.50`), получает один ведущий пробел, чтобы Excel не вычислял подброшенную командную строку вида `-2+3` или `=cmd|...` как формулу; числовые ячейки не изменяются. CSV-файл записывается даже без единой строки данных: `scheduled-tasks.csv`, `devices-problems.csv`, `drivers.csv` и `events.csv` тогда содержат только строку заголовка, а файлы монитора всегда начинаются с заголовка.

## Поиск майнера или пожирателя ресурсов

Криптомайнер прячется двумя способами: работает только когда компьютером никто не пользуется (простой, заблокированный экран) и маскируется под системный процесс. Разовый снимок этого не поймает; запись - поймает.

### 1. Запись

- **Интерактивно:** `WinDebug.cmd monitor` (или пункт меню 3). Оставьте окно открытым, поработайте за компьютером как обычно несколько часов и обязательно оставьте его в покое хотя бы на 30-60 минут (заблокированный экран подходит). Монитору нужно не меньше 20 сэмплов (около 3,5 минут при интервале 10 с) в **обоих** состояниях - активном и простое - чтобы их сравнить; чем больше, тем лучше.
- **Несколько дней без присмотра:** `WinDebug.cmd -InstallTask` (или пункт меню 6) регистрирует пользовательскую задачу входа с именем **`WinDebug Monitor`**, которая скрыто запускает монитор через минуту после каждого входа в систему. Дайте ей поработать несколько дней обычного использования. Позже удалите её командой `WinDebug.cmd -UninstallTask` (пункт меню 7). Не перемещайте папку `win-debug`, пока задача существует - задача ссылается на папку, из которой была установлена.
- По возможности запускайте монитор **с правами администратора**: без них путь, командная строка, владелец, подпись и хэш процессов SYSTEM и служб (обычно 100-200 штук) остаются неизвестными, и майнер, установленный как служба, виден только по поведению CPU/GPU.
- Дополнительно: `-TrackShortLived` записывает и процессы, живущие всего несколько секунд (через события создания процессов WMI).

### 2. Остановка

Любой из способов завершает запись корректно:

- создайте пустой файл с именем **`STOP`** в папке сеанса (`reports\<ПК>_<дата>_monitor\`);
- выполните `WinDebug.cmd -StopMonitor` (пункт меню 8) - создаёт файл STOP для каждого работающего монитора и ждёт до 30 с. Завершается одним из трёх сообщений: `Monitor stopped.` (код выхода 0), `STOP signal sent; the monitor did not confirm within 30 s - check monitor.log.` (код выхода 0; монитор остановится на следующем сэмпле, файл STOP остаётся на месте) или `No running monitor found.` (код выхода 3);
- нажмите **Q** или **Ctrl+C** в окне монитора;
- запускайте с `-DurationMinutes <n>`.

Закрытие окна крестиком или `taskkill` тоже останавливает монитор, теряется максимум одна неполная строка; оставшийся маркер `monitor.running` игнорируется, как только его процесс исчез.

### 3. Анализ

`WinDebug.cmd analyze` (пункт меню 4) берёт самую новую папку `*_monitor` внутри `reports\`; для другой укажите `-SessionPath <папка>`. Analyze никогда не запрашивает права администратора и может работать даже пока монитор ещё пишет. Откройте `report.md` в папке сеанса.

### 4. Чтение отчёта

- **Verdict** (вердикт) - ответ. Либо `Nothing suspicious found` с причинами (нет майнерских токенов, нет процесса, активного в простое, нет использования GPU Compute, нет маскировки, нет портов пулов, максимальные набранные баллы), либо три главных подозреваемых с баллами и классом. `Inconclusive` означает, что нет пригодных наблюдений процессов либо часть данных не удалось прочитать или оценить; проверьте ошибки сбора и запишите новую сессию. Найденные подозреваемые остаются в отчёте, даже если другие данные неполны. `near-certain indicator fired` означает, что замечена майнерская командная строка или обнаружение Defender - считайте такой процесс вредоносным, пока не доказано обратное.
- **Баллы.** 22 индикатора начисляют баллы по каждому исполняемому файлу (см. [docs/analyze-scoring.md](docs/analyze-scoring.md)): **8-14 = Suspicious** (подозрительный), **15+ = Highly suspicious** (крайне подозрительный). Майнерские токены (20 баллов) и обнаружения Defender (15) никогда не гасятся; действительная подпись известного производителя в System32/Windows/Program Files вычитает 6, известный тяжёлый, но легитимный фоновый процесс (Defender, индексатор поиска, Windows Update, OneDrive, браузеры, WSL, службы производителей GPU) вычитает 4 из ресурсных индикаторов. Сырой балл и текст каждого индикатора сохраняются в `suspects.csv`, так что погашенное срабатывание всегда можно перепроверить. Если порог никто не достиг, отчёт всё равно показывает пять максимальных баллов «для прозрачности».
- **Idle vs active** (простой и работа) - сильнейший признак майнера: средняя загрузка CPU каждого процесса, пока компьютером никто не пользовался, против загрузки во время работы. Процесс с >= 5 % CPU в простое и как минимум вдвое выше своего активного среднего получает индикатор I1 (6-8 баллов). Если в одном из состояний меньше 20 сэмплов, раздел сообщает `insufficient data` и показывает только список лидеров в простое - записывайте дольше.
- **Suspicious processes** (подозрительные процессы) - по каждому: баллы, индикаторы с доказательствами, путь, подписант, SHA256 со **ссылкой VirusTotal** (`https://www.virustotal.com/gui/file/<sha256>`). Ссылку открываете вы сами; инструмент никогда не обращается к VirusTotal. `SKIPPED_SIZE` означает, что файл больше 64 МБ и не хэшировался. `?` означает, что индикатор нельзя оценить, так как путь неизвестен (запуск без прав администратора). Список *Re-run the monitor elevated to inspect these processes* называет процессы SYSTEM/служб, чьё потребление ресурсов сработало, но файл проверить не удалось.
- **Network endpoints of interest** - соединения с известными портами майнинговых пулов (3333, 4444, 14444 и другие), «голые» IP-адреса без DNS-имени, адреса процессов с баллами.
- **Appendix** - методика, заметки о ложных срабатываниях, пробелы в данных, след самого монитора.

### Чего ожидать (ложные срабатывания)

- **Легитимные работники простоя:** проверки Defender (`MsMpEng`), индексатор поиска, рабочие процессы Windows Update (`TiWorker`, `MoUsoCoreWorker`), OneDrive, «Фотографии» (использует GPU Compute для распознавания лиц), резервное копирование, `svchost`, обслуживающий Update/BITS/Оптимизацию доставки. Они гасятся, но всё равно появляются в таблице простоя.
- **GPU:** браузеры, Electron-приложения (VS Code, Discord, Telegram, Spotify) и игры используют движки 3D/Video даже свёрнутыми - баллы даёт только движок **Compute**. Ollama / LM Studio / Python с torch - это вычисления, установленные пользователем.
- **Командные строки:** майнерским токеном считается только URL пула (`--url=stratum...`, `-o stratum...`, `-o host:port`) - обычный `--url=https://...` вспомогательных процессов Electron/Chromium (Spotify, VS Code, Яндекс Браузер) не совпадает. Аргументы скриптовых хостов разделены на две силы: *слабые* параметры запуска (`-ExecutionPolicy Bypass`, `-NoProfile`, `-WindowStyle Hidden`, `-NonInteractive`) носят только информационный характер - любой PowerShell, запущенный так (оболочки IDE, запланированные скрипты, сам win-debug), попадает в список, но получает не больше 2 баллов, - а *сильные* признаки доставки полезной нагрузки (`-EncodedCommand`, `DownloadString`, `IEX`, `FromBase64String`, `scrobj.dll`, `certutil -decode`, `bitsadmin`, `curl`/`wget`, URL `http(s)://`, `javascript:`/`vbscript:`, `mshta` с URL) - это и есть красные флаги.
- **Без подписи, но легитимные:** инди-игры, инструменты Python/Node, портативные программы, самосборные утилиты (по 2 балла за расположение и подпись).
- **Сам монитор:** его `powershell.exe` помечен `Self` и исключён; `WmiPrvSE.exe` (хост провайдеров WMI) показывает 1-2 % CPU из-за самого опроса. Никто не должен «найти» монитор.
- **Машины разработчиков:** git, bash, python и conhost, запускаемые десятки раз, включают индикатор перезапусков-«сторожей» (4 балла, ниже порога).

## Справочник по командной строке

Формы лаунчера (лаунчер делает паузу в конце, кроме режима monitor, и печатает `WinDebug exited with code N.` при ненулевом коде):

```
WinDebug.cmd                                  интерактивное меню
WinDebug.cmd inventory|disk|monitor|analyze|all [параметры]
WinDebug.cmd -Mode Disk -Drives C -NoElevate   форма «сначала параметры»: всё передаётся в WinDebug.ps1 без изменений
WinDebug.cmd -StopMonitor
WinDebug.cmd -InstallTask -IntervalSeconds 10
```

Напрямую: `powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\WinDebug.ps1 -Mode <Режим> [параметры]`. Полная справка: `Get-Help .\WinDebug.ps1 -Full`.

| Параметр | Значение | По умолчанию |
|---|---|---|
| `-Mode Inventory\|Disk\|Monitor\|Analyze\|All\|Menu` | Что запускать. | `Menu` |
| `-OutputRoot <папка>` | Папка, в которой создаётся по подпапке на каждый запуск. | `<папка скрипта>\reports` |
| `-IntervalSeconds <5-3600>` | Monitor: секунд между сэмплами. 5 с - нижняя граница, а не рекомендация. | `10` |
| `-DurationMinutes <0-100000>` | Monitor: остановиться через n минут; 0 = работать до файла STOP, `-StopMonitor`, Q или Ctrl+C. | `0` |
| `-SessionPath <папка>` | Analyze: анализируемый сеанс монитора. | самая новая папка `*_monitor` в OutputRoot |
| `-Drives C,D` | Disk: какие тома сканировать (принимаются `C`, `C:` и `C,D`). | все фиксированные тома с буквой |
| `-TopN <5-500>` | Число верхних элементов в отчётах Disk и Analyze. | `50` |
| `-Deep` | Необязательные медленные шаги: Inventory проверяет подпись Authenticode каждого файла автозагрузки (а не только помеченных) и перечисляет все подписанные драйверы; Disk устраняет двойной подсчёт жёстких ссылок в `%windir%` (примерно +30 с). | выкл. |
| `-NoElevate` | Никогда не запрашивать права администратора; работать с текущими правами. | |
| `-Elevate` | Перезапуститься с повышением (запрос UAC) без вопроса. | |
| `-InstallTask` | Зарегистрировать пользовательскую задачу входа `WinDebug Monitor` (использует `-OutputRoot` и `-IntervalSeconds`) и выйти. | |
| `-UninstallTask` | Удалить задачу входа и выйти. | |
| `-StopMonitor` | Попросить все работающие мониторы в OutputRoot остановиться (создаёт их файлы STOP, ждёт до 30 с) и выйти: `Monitor stopped.` (0), `STOP signal sent; the monitor did not confirm within 30 s - check monitor.log.` (0) или `No running monitor found.` (3). | |
| `-TrackShortLived` | Monitor: дополнительно записывать короткоживущие процессы через события создания процессов WMI (процессы короче 2 с пропускаются). | выкл. |
| `-Verbose` | Дополнительно показывать строки DEBUG инструмента в консоли (в `run.log` / `analyze.log` они пишутся всегда); монитор при этом записывает в `monitor.log` по одной строке DEBUG на каждый шаг сбора. | |

`-Elevated` - внутренний параметр (ставится перезапущенной копией с повышенными правами). Analyze и Menu никогда не запрашивают повышение; в меню оно доступно пунктом **A**. Из меню выходит только **Q** (или Ctrl+C); пустой Enter просто перерисовывает меню. Параметры только именованные: лишний позиционный токен (например, `D` из `-Drives C,D` без кавычек, разбитого `cmd.exe` по запятой) - это ошибка привязки (код выхода 1), а не тихая подстановка в `-OutputRoot`.

Коды выхода (передаются в `%ERRORLEVEL%` через `WinDebug.cmd`):

| Код | Значение |
|---|---|
| 0 | Успех |
| 1 | Необработанная ошибка или ошибка записи отчёта - см. `run.log` или `analyze.log` в папке отчёта (частичные файлы сохраняются); а также собственные ошибки привязки параметров PowerShell (нечисловой `-TopN`, лишний позиционный токен) |
| 2 | Запуск с сетевого / UNC-пути - скопируйте в локальную папку |
| 3 | Монитор уже работает в этом OutputRoot (`-Mode Monitor`; отказ происходит до создания какой-либо папки) или нечего останавливать (`-StopMonitor`: `No running monitor found.`) |
| 4 | Отсутствует файл в `lib\` - скачайте инструмент заново целиком |
| 5 | Неверные параметры (печатается текст подсказки): неизвестный `-Mode`, `-IntervalSeconds` / `-DurationMinutes` / `-TopN` вне диапазона, папка сеанса для Analyze отсутствует, не найдена в OutputRoot или не является сеансом монитора (нет `samples_*.csv`, `procs_*.csv` или `procsum.json` - папка остаётся нетронутой), либо меню запущено с перенаправленным вводом |
| 6 | Не удалось установить/удалить задачу входа (например, `-UninstallTask`, когда задачи нет) |

## Что работает без администратора и что требует его

Инструмент никогда не падает из-за нехватки прав. Всё, что не удалось прочитать, помечается `(requires administrator)` в отчёте и перечисляется в разделе **Skipped (requires administrator)** в конце `summary.md` / `report.md`.

| Работает без администратора | Требует администратора |
|---|---|
| Оборудование, ОС, обновления, драйверы, устройства, установленные программы, ваши приложения Store и автозагрузка, службы, видимые вам запланированные задачи, состояние Defender и возраст сигнатур, состояние брандмауэра/UAC/SmartScreen, локальные учётные записи, настройки сети, файл hosts, отчёт о батарее, журналы событий Application/System/Defender/TaskScheduler/PowerShell, снимок производительности | Счётчики SMART / надёжности дисков, бит «грязного» тома, **исключения** Defender, запланированные задачи, видимые только SYSTEM, журнал **Security**, события Diagnostics-Performance о времени загрузки, события Storport о задержках диска, папки `LiveKernelReports` и WER `ReportQueue`, размер индекса Windows Search, приложения Store и автозагрузка **других пользователей**, путь и командная строка процессов других пользователей |
| Disk: ваш профиль, все доступные вам папки/файлы, кандидаты на очистку в вашем профиле и общедоступных системных папках, установленные приложения, настройки Контроля памяти (Storage Sense) | Disk: состояние BitLocker, `Windows\Temp` и `SystemTemp`, Prefetch, индекс Windows Search, история проверок Defender, теневое хранилище / System Volume Information (точки восстановления), профили, кэши и Корзины других пользователей, корень `WindowsApps` |
| Monitor: CPU, GPU, память, IO, потоки/дескрипторы, TCP-соединения и кэш DNS для **каждого** процесса; путь, командная строка, владелец, подпись и SHA256 для ваших процессов; все журналы событий, кроме Security | Monitor: путь, командная строка, владелец, подпись и SHA256 процессов SYSTEM, служб и других пользователей. Журнал Security (создание процесса 4688, создание задачи 4698) монитор не опрашивает вовсе; запуск без повышения прав перечисляет его в разделе *Skipped (requires administrator)* |
| Analyze: всё (он только читает сеанс) | Analyze наследует пробелы сеанса: индикаторы о расположении, подписи, командной строке и цепочке родителей показывают `?` для процессов, которые монитор не смог рассмотреть |
| Задача входа: устанавливается с уровнем *Limited* (монитор при входе работает без прав администратора) | Задача входа с уровнем *Highest*: устанавливайте её из сеанса с повышенными правами |

Пустой или некорректный `-Drives` отклоняется с кодом 5 до создания папки отчёта. Такой ввод не приводит к сканированию всех дисков.

## Конфиденциальность

Отчёты предназначены для того, кто запускает инструмент. Они содержат персональные данные:

- имя компьютера, имя пользователя `ДОМЕН\пользователь` и его SID, сборку ОС, признак запуска с повышенными правами;
- серийные номера оборудования (дисков; на ноутбуках - батареи в `battery-report.xml`, «сыром» отчёте `powercfg`, вместе с **историей включений и режима ожидания за несколько недель**), MAC- и IP-адреса, DNS-серверы, активные записи `hosts`, имена локальных учётных записей;
- список установленных программ и приложений Store, элементы автозагрузки, действия запланированных задач, пути служб;
- каждый работающий процесс с **полной командной строкой**: `processes-snapshot.csv` (Inventory), `procmeta.csv` / `procsum.json` (Monitor), `report.md` / `suspects.csv` / `process-summary.csv` / `analysis.json` (Analyze). Командные строки могут содержать токены или ключи, переданные аргументами, поэтому значения, похожие на учётные данные (`password=...`, `--token x`, `PrivateKey = ...`, `"apikey": "..."`, `https://user:secret@host`, `?token=...`), заменяются на `***` перед записью; имя ключа сохраняется, а адреса майнинговых пулов и кошельков намеренно остаются видимыми - это улики. **Маскирование эвристическое** (по мере возможности): секрет, переданный в необычной форме, всё равно попадёт в файлы;
- режим Disk: имена и пути профилей, имена файлов в «Загрузках», имена папок OneDrive, **отображаемые имена профилей браузеров** (обычно это имя учётной записи, в которую выполнен вход), **имя файла Outlook `.ost`** (= адрес почтового ящика), названия игр;
- Monitor/Analyze: удалённые IP-адреса и порты, имена из кэша DNS, наличие окон, фрагменты журналов событий (детали установки служб, текст блоков скриптов PowerShell до 300 символов - маскируются так же), хэши SHA256 исполняемых файлов.

Первый раздел каждого `summary.md` / `report.md` повторяет это одной строкой *Privacy*. Ничего не отправляется и не запрашивается в сети - инструмент вообще не устанавливает сетевых соединений; ссылки VirusTotal - обычные URL, которые открываете вы. Папка `reports\` указана в `.gitignore`. Просмотрите файлы, прежде чем делиться ими с кем-либо, и удалите их, когда закончите.

## Устранение неполадок

| Симптом | Причина / решение |
|---|---|
| `This folder is on a network/UNC path` или код выхода 2 | Инструмент лежит на сетевом ресурсе, по пути `\\server\...` или `\\wsl.localhost\...`. Скопируйте папку на локальный диск (`C:\Tools\win-debug`) и запускайте оттуда. |
| `... is not digitally signed`, `AuthorizationManager check failed` | Файлы всё ещё несут отметку «загружено из интернета» (ZIP не разблокирован) или лежат на сетевом пути. Скопируйте локально, затем выполните в папке `Get-ChildItem -Recurse \| Unblock-File`. |
| PowerShell отказывается запускать скрипт, хотя `WinDebug.cmd` передаёт `-ExecutionPolicy Bypass` | Политика выполнения задана групповой политикой (`MachinePolicy` / `UserPolicy` в `Get-ExecutionPolicy -List`); `Bypass` её не переопределяет. Так бывает на управляемых (корпоративных) ПК - обратитесь к администратору. Домашние ПК это не затрагивает. |
| Код выхода 3, `A monitor is already running` | На одну папку отчётов - один монитор. Остановите его (`WinDebug.cmd -StopMonitor`) или подождите; маркер `monitor.running`, чей процесс уже не существует, игнорируется автоматически. |
| Код выхода 5 и текст подсказки вместо меню | Меню нужна настоящая консоль; при перенаправленном вводе (планировщик, удалённая оболочка) укажите `-Mode` явно. |
| Код выхода 5, `Not a monitor session (...)` или `No monitor session found under ...` | Analyze принимает только папку, содержащую `samples_*.csv`, `procs_*.csv` или `procsum.json`; всё остальное отвергается без записи в папку. Сначала запишите сеанс или укажите `-SessionPath` на настоящую папку `*_monitor`. |
| Код выхода 1, `A positional parameter cannot be found that accepts argument 'D'` | `cmd.exe` разбил `-Drives C,D` без кавычек по запятой. Возьмите значение в кавычки (`-Drives "C,D"`) или повторите ключ (`-Drives C -Drives D`); лишний токен отвергается, а не принимается за `-OutputRoot`. |
| `STOP signal sent; the monitor did not confirm within 30 s` | Файл STOP записан, но монитор не завершился за 30 с (долгий сэмпл, ПК под нагрузкой). Он остановится при следующей проверке; загляните в `monitor.log` в папке сеанса. Больше ничего делать не нужно. |
| `Missing ...\lib\...` / код выхода 4 | Неполная распаковка; скачайте ZIP заново и распакуйте всё. |
| Inventory сообщает о недоступных счётчиках производительности (`CPU-COUNTERS`), Monitor пишет `Process performance counters returned no data`, либо в `run.json` указано `GpuCounterMode: none` при наличии настоящего GPU | Повреждён реестр счётчиков производительности. В командной строке **от администратора** выполните `lodctr /R` (дважды, если первая попытка сообщает об ошибке), перезагрузитесь и запустите снова. Счётчикам GPU по процессам также нужен драйвер WDDM от производителя видеокарты (не «Базовый видеоадаптер (Майкрософт)»). |
| При входе в систему на долю секунды мигает окно консоли | Это задача `WinDebug Monitor` запускает `powershell.exe -WindowStyle Hidden` - Windows ненадолго показывает консоль, прежде чем скрыть её. Безвредно. |
| `WmiPrvSE.exe` и какой-то `powershell.exe` нагружают CPU, пока работает монитор | Это сам монитор: его `powershell.exe` (несколько процентов одного ядра при интервале по умолчанию, помечен `Self` и исключён из отчётов) и хост провайдеров WMI (1-2 %), отдающий счётчики производительности. На очень медленных машинах увеличьте `-IntervalSeconds`; по умолчанию 10 с. |
| Сэмплы монитора помечены `Overrun` | Сбор занял больше интервала - нормально для первых двух сэмплов и первой минуты (очередь подписей/хэшей). Частые переполнения позже означают, что интервал слишком короток для этого ПК. |
| Режим Disk завершился сообщением `scan interrupted by Ctrl+C; partial totals discarded` | Вы нажали Ctrl+C во время обхода тома. Обход останавливается за миллисекунды, а его частичные итоги отбрасываются, а не выдаются за факты; запустите режим Disk ещё раз (или `-Drives` для одного тома), когда компьютер можно оставить в покое. |
| Находка Inventory `MEM-POOL` на ПК с WSL2 / Hyper-V или `CPU-BUSY-IDLE` сразу после запуска чего-то тяжёлого | Ожидаемо: виртуализация и крупные драйверы GPU используют невыгружаемый пул; правило про CPU не может знать, бездействовали ли вы во время снимка. При наличии гипервизора (`HypervisorPresent`) или работающего процесса `vmmem` / `vmmemWSL` правило `MEM-POOL` использует порог 2,5 ГБ и выдаёт только Info. |
| Режим Disk пишет `Directory walker: .NET fallback` | Не удалось скомпилировать вспомогательный модуль C# (`%TEMP%` только для чтения, нет компилятора .NET Framework). Сканирование работает, но медленнее, а занимаемый размер сжатых/разреженных файлов приблизителен. |
| Analyze: `insufficient data` в разделе *Idle vs active* | В сеансе меньше 20 сэмплов в одном из двух состояний. Записывайте дольше, охватывая и обычную работу, и простой. |

## Как это устроено

- Чистый Windows PowerShell 5.1 плюс два исходника на C#, компилируемых в памяти через `Add-Type` (`lib\native\FastWalker.cs` - обходчик каталогов на `FindFirstFileEx` с учётом занимаемого размера и точек повторной обработки; `lib\native\Native.cs` - владелец процесса из токена, время простоя пользователя через `GetLastInputInfo`, состояние блокировки сеанса). Никаких внешних двоичных файлов, модулей и загрузок.
- Данные берутся из CIM/WMI (`Get-CimInstance`, включая «сырые» классы счётчиков производительности), реестра и .NET API. Вывод локализованных консольных утилит никогда не разбирается; единственные внешние программы - `schtasks.exe /query` (только подсчёт строк) и `powercfg.exe /batteryreport` (пишет в папку отчёта).
- Независимость от региональных настроек заложена в конструкцию: культура потока переключается на инвариантную, а каждое число форматируется и разбирается явно, поэтому файлы одинаковы на русской, немецкой и английской Windows.
- Только чтение: инструмент пишет только в свою папку отчётов (плюс, по явному запросу, одну пользовательскую задачу планировщика). Никаких удалений, записи в реестр, изменений служб, действий по очистке.
- Каждый элемент сбора изолирован: один отказавший класс WMI или журнал событий никогда не прерывает запуск; отказ перечисляется в разделе *Collection errors*.

## Участие в разработке

Из локальной копии на Windows запустите `powershell -NoProfile -ExecutionPolicy Bypass -File tests\Invoke-FunctionalChecks.ps1 -IncludeMonitor`: это проверки поведения и короткий цикл Monitor / STOP / Analyze. Они и самопроверка репозитория автоматически запускаются в GitHub Actions.

- Целевая платформа - только **Windows PowerShell 5.1**: без синтаксиса PowerShell 7 (`??`, `?.`, тернарный оператор, `-Parallel`), без внешних модулей, без `Start-Job`/runspace.
- Без алиасов (`?`, `%`, `select`, `gci`...), полные имена параметров, утверждённые глаголы, `[CmdletBinding()]` у каждой функции, везде `-LiteralPath`.
- Никогда `Get-WmiObject`, `Get-Counter`, `Win32_Product`; никогда не разбирать локализованный вывод консольных утилит.
- Кодировки исходников: `.ps1` и `.cs` - UTF-8 **с BOM** и CRLF; `WinDebug.cmd` - ASCII с CRLF; `.md`/`.json` - UTF-8 без BOM и LF (обеспечивается `.gitattributes`).
- Всё, что пишется в файлы, должно быть независимым от региональных настроек (точка как разделитель, время в ISO) - используйте помощники из `lib\Common.ps1`.
- Инструмент остаётся «только для чтения» и должен корректно работать без прав администратора, помечая пробелы буквальным текстом `(requires administrator)`.
- Никогда не запускайте «голый» `powershell.exe`: лаунчер, перезапуск с повышением прав и задача входа используют полный путь к хосту Windows PowerShell 5.1 (`$PSHOME\powershell.exe` / `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`); самопроверка отмечает «голые» вхождения.
- Перед pull request запустите самопроверку: `powershell -NoProfile -ExecutionPolicy Bypass -File tests\Invoke-Checks.ps1` (Pester не нужен; код выхода 1 при любой ошибке). Кроме синтаксиса, кодировок, алиасов, глаголов и запрещённых API она проверяет гигиену исходников (уровни `Write-Log`, «голый» `powershell.exe`, устаревшие ссылки на спецификацию), что ни одна функция не присваивает локальную переменную, отличающуюся от её параметра только регистром (`$Path` и `$path` в PowerShell - одна переменная), что каждый `-RuleId` из `lib\*.ps1` документирован в `docs\inventory-rules.md` или `docs\analyze-scoring.md` (документированный, но больше не используемый в коде идентификатор - только предупреждение), поведение помощников `lib\Common.ps1` (регулярные выражения правил, класс расположения, экранирование аргументов, защита CSV, `Export-CsvInvariant -Columns`, `Hide-WdSecret`, пропуски из-за прав администратора vs ошибки сбора, строка Privacy) и документированные коды выхода `WinDebug.ps1` (последняя группа пропускается, если репозиторий лежит на UNC-пути). Сам инструмент запускайте из локальной копии - UNC-пути он отвергает.
- Архитектура, соглашения и общий API описаны в [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Данные правил (регулярные выражения, списки портов, доверенные подписанты) находятся в `lib\Common.ps1` и общие для всех модулей; каждый новый идентификатор правила документируйте строкой таблицы в соответствующем файле `docs\` - самопроверка завершается ошибкой, если идентификатор не документирован.

## Отказ от ответственности

win-debug - диагностический помощник, а не антивирус. Он собирает улики и ранжирует их; он ничего не удаляет и может ошибаться в обе стороны. Вердикт `Highly suspicious` заслуживает проверки на VirusTotal и полного автономного сканирования вашим антивирусом; вердикт `Nothing suspicious found` означает лишь то, что за записанный период ничто не вело себя как майнер. Используйте отчёты вместе со здравым смыслом и помните, что они содержат персональные данные.
